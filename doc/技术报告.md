# Graph-Constrained Reasoning 技术报告

## 项目概述

**项目名称**: Graph-Constrained Reasoning (GCR)  
**论文**: [Graph-constrained Reasoning: Faithful Reasoning on Knowledge Graphs with Large Language Models](https://arxiv.org/abs/2410.13080)  
**发表会议**: ICML 2025

### 核心贡献

Graph-constrained Reasoning (GCR) 是一个创新性框架,旨在解决大语言模型(LLM)在知识图谱(KG)推理中的幻觉问题。该框架通过将知识图谱的结构化信息与大语言模型的非结构化推理能力相结合,实现了零幻觉的可信推理路径生成。

#### 1.2 Graph-Constrained Decoding

**核心算法** (`src/graph_constrained_decoding.py`):

该模块实现了约束解码的核心逻辑,通过以下机制确保生成的推理路径严格遵循知识图谱结构:

1. **约束标志检测**: 通过特殊的开始/结束 token 标识约束解码区域
2. **Token 过滤**: 在约束区域内,只允许生成 Trie 中存在的 token 序列
3. **无缝集成**: 通过 `prefix_allowed_tokens_fn` 接口与 HuggingFace Transformers 集成

**关键代码片段**:
```python
def allowed_tokens_fn(self, batch_id: int, sent: torch.Tensor):
    # 检查是否在约束解码区域
    constrained_flag, L_input = self.check_constrained_flag(sent)
    
    if constrained_flag:
        # 从 Trie 获取允许的 token
        allow_tokens = self.trie.get(sent.tolist()[L_input:])
        if len(allow_tokens) == 0:
            return self.all_tokens  # 回退到无约束
    return allow_tokens
```

#### 1.3 图索引构建 (`workflow/build_graph_index.py`)

**功能**: 为知识图谱构建路径索引

**算法流程**:
1. 从数据集加载知识图谱三元组
2. 构建 NetworkX 图结构(支持有向/无向图)
3. 从问题实体出发进行 DFS 遍历
4. 收集指定长度内的所有路径
5. 保存为 Hugging Face Dataset 格式

**核心代码** (`src/utils/graph_utils.py`):
```python
def dfs(graph, start_node_list, max_length):
    """深度优先搜索收集所有路径"""
    def dfs_visit(node, path):
        if len(path) > max_length:
            return
        for neighbor in graph.neighbors(node):
            rel = graph[node][neighbor]["relation"]
            new_path = path + [(node, rel, neighbor)]
            if len(new_path) <= max_length:
                path_lists.add(tuple(new_path))
            dfs_visit(neighbor, new_path)
```

### 3. 完整推理流程

#### Stage 1: Graph-Constrained Decoding

**目标**: 使用轻量级 KG-specialized LLM 生成 KG-grounded 推理路径

**流程** (`workflow/predict_paths_and_answers.py`):
1. 加载问题数据集
2. 为每个问题构建 Trie 索引(基于 DFS 收集的路径)
3. 构建提示词 (使用 `PathGenerationWithAnswerPromptBuilder`)
4. 调用 `generate_sentence()` 进行约束解码
5. 使用 beam search 生成 top-k 推理路径和候选答案
6. 保存结果到 `results/GenPaths/`

**关键特性**:
- 零幻觉: 所有生成的路径都必然存在于知识图谱中
- 高效: 使用 Trie 数据结构实现 O(log n) 复杂度的 token 过滤
- 可扩展: 支持 group-beam search 生成多样化的路径

#### Stage 2: Graph Inductive Reasoning

**目标**: 使用通用 LLM 对多个推理路径进行归纳推理

**流程** (`workflow/predict_final_answer.py`):
1. 加载 Stage 1 生成的推理路径和候选答案
2. 构建包含多个路径的提示词
3. 调用 GPT-3.5-turbo 或 GPT-4o-mini
4. 综合多个推理路径生成最终答案
5. 评估答案准确性

**优势**:
- 利用 LLM 的归纳推理能力
- 无需额外训练
- 可解释性强(提供完整推理路径)

## 核心算法创新

### 1. KG-Trie 约束机制

**问题**: 传统 LLM 在 KG 推理时容易产生幻觉(生成不存在的关系或实体)

**解决方案**: 
- 将 KG 路径序列化为 token 序列并构建 Trie 索引
- 在解码时动态过滤非法 token,确保生成路径必然在 KG 中存在
- 通过特殊 token 标记约束区域,允许灵活的混合生成

**优势**:
- **零幻觉**: 理论上保证 100% 的路径真实性
- **高效**: O(L) 复杂度的路径验证,其中 L 为路径长度
- **灵活**: 可与任何 HuggingFace 兼容模型集成

### 2. 两阶段推理架构

**Stage 1 (Specialized)**: 
- 使用轻量级 LLM (0.5B-8B 参数)
- 专注于 KG 结构化导航
- 低成本、可部署

**Stage 2 (General)**:
- 使用通用 LLM (GPT-3.5/GPT-4)
- 归纳推理和答案选择
- 无需训练

**优势**: 兼顾准确性和效率,可在资源受限环境部署

### 3. 图索引优化

- **多进程并行**: 支持 N 进程并行构建索引
- **可配置路径长度**: 灵活控制索引粒度(K=2 或 3)
- **有向/无向图支持**: 适应不同 KG 类型
- **懒加载**: 评估时可动态构建索引

## 技术挑战与解决方案

### 挑战 1: 大规模 KG 的内存占用
**解决方案**: 
- 使用 Marisa Trie 压缩存储
- 支持按需加载索引
- 懒加载策略

### 挑战 2: 长路径的组合爆炸
**解决方案**:
- 限制路径最大长度 (K=2 或 3)
- DFS 剪枝策略
- Beam search 控制候选数量

### 挑战 3: 多样化推理路径
**解决方案**:
- Group-beam search 生成多样化候选
- Stage 2 归纳推理综合多路径
- 支持 top-k 路径输出
