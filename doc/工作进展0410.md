# 4月10日工作进展

## 一、本周工作目标

本周的重点工作，是围绕 `interactive_client` 目录搭建一个面向图约束推理场景的交互式客户端原型，把原来更偏离线实验的图约束生成链路，整理成一个能够本地加载模型、接受用户问题、自动抽取实体、构造局部子图并执行约束解码的可交互流程。

目标上主要聚焦三件事：

1. 搭建交互式推理入口，支持单轮与多轮问答。
2. 将实体抽取、子图裁剪、路径候选构造接到同一条推理链路中。
3. 复用项目现有的图约束解码与 prompt 构造能力。


## 二、本周完成的主要工作

### 1. 完成交互式客户端整体框架搭建

本周新增了 `interactive_client` 目录，包括：

- `graph_reasoning_client.py`
- `graph_store.py`
- `entity_extractor.py`
- `config.py`
- `default_config.json`
- `README.md`
- `KG.json`

其中，`graph_reasoning_client.py` 作为主入口，已经把“问题输入 -> 实体识别 -> 局部子图构建 -> trie 构造 -> 图约束生成 -> 结果输出”整合为一条完整流程。当前支持两种使用方式：

1. 交互式 REPL 模式，适合连续提问和调试。
2. `--question` 单次提问模式，适合脚本化调用和快速验证。

同时补充了 `/config`、`/quit` 等基础交互命令，便于查看当前配置和退出会话。

### 2. 完成配置管理与命令行覆盖机制

围绕 `config.py` 和 `default_config.json`，本周完成了交互客户端的配置封装，主要包括：

- 使用 dataclass 统一管理模型、图谱、生成、实体匹配等参数。
- 支持从 JSON 配置文件加载默认配置。
- 支持通过命令行参数覆盖关键字段，如模型路径、KG 文件、beam 数、最大生成长度、子图 hop 数等。
- 支持相对路径自动解析为仓库绝对路径。
- 增加基础配置校验，避免模型路径、图文件或参数非法时直接进入运行阶段。



### 3. 完成知识图谱加载与局部子图裁剪模块

`graph_store.py` 完成了知识图谱数据读取和局部子图抽取逻辑，主要实现了：

- 支持从 JSON 或 JSONL 风格文件读取图数据。
- 对三元组进行清洗、去重和顺序保留。
- 基于起始实体执行 K-hop 子图抽取。
- 支持对局部子图三元组数量进行上限控制，避免过大子图影响后续 trie 构建和生成效率。

基于当前 `interactive_client/KG.json` 的静态统计结果：

- 图谱记录数约为 793150 条。
- 去重后三元组约为 787053 条。
- 覆盖实体约为 112243 个。



### 4. 完成实体抽取与交互式实体选择能力

`entity_extractor.py` 本周完成了一个轻量实体抽取模块，目标是在不额外引入复杂 NER 流程的情况下，为交互式问答提供可用的实体定位能力。当前已实现：

- 文本归一化处理，降低标点、空白和大小写差异带来的匹配干扰。
- 方括号、圆括号等显式实体提示的优先抽取。
- 基于字符重叠度和字符串相似度的候选实体打分。
- 手动输入实体时的实体解析与回填。

在多候选场景下，系统会向用户展示候选实体及分数，并支持：

- 直接回车使用默认高分实体。
- 输入候选编号进行选择。
- 手动输入自定义实体名进行解析。

这部分工作提升了客户端在真实提问场景下的可用性，也减少了完全依赖人工指定实体的门槛。

### 5. 打通局部路径构造与图约束解码链路

`graph_reasoning_client.py` 已经接入项目现有的图约束推理能力，完成了以下关键工作：

- 从选中的实体出发，抽取局部子图。
- 调用现有图工具构建局部图结构。
- 基于 DFS 搜索候选路径。
- 对候选路径进行排序和截断，控制 trie 规模。
- 调用 `ChinesePathGenerationWithAnswerPromptBuilder` 构造 prompt 和前缀 trie。
- 调用 `GraphConstrainedDecoding` 与 `PathEndStoppingCriteria` 执行约束生成。
- 对输出路径做归一化、去空值、去重处理。

这意味着交互客户端并不是重新实现一套解码逻辑，而是在复用现有图约束生成框架的基础上，补齐了“交互入口 + 局部图构造 + 运行组织”这层能力。
