# 图约束路径生成 GRPO 微调方案

## 第一部分：核心架构设计

传统强化学习（如 PPO）容易崩溃，且显存开销大（通常需要同时加载 4 个模型）。本方案采用当前推理任务主流范式：**GRPO**。

### 1.1 基座模型
- 建议模型规模：**7B/8B Instruct**（如 `Qwen2.5-7B-Instruct`、`Llama-3-8B-Instruct`）
- 训练方式：**LoRA/PEFT**
- 在 A800 80GB 上显存安全余量充足

### 1.2 GRPO（群体相对策略优化） 核心机制
- **不训练独立 Critic（价值网络）**，直接降低显存占用与训练复杂度
- **相对打分**：
  - 针对同一问题，一次生成 `G` 条路径（建议 `G=10`）
  - 对组内路径打分并标准化，得到优势值（Advantage）
  - 高分路径概率上调，低分路径概率下调

### 1.3 约束与探索融合策略
- **Rollout（探索生成）阶段**：注入 `prefix_allowed_tokens_fn`
  - 保证生成路径 **100% 图谱合法**
- **Update（梯度更新）阶段**：撤销约束
  - 让损失函数直接作用于模型底层概率分布

## 第二部分：数据准备方案

无需复杂 JSONL 对齐逻辑，可在内存中构建 PyTorch Dataset，输出两类信息：

### 2.1 输入指令（Prompt）
将 `question` 与 `q_entity` 组织为标准对话模板（Chat Template）。

建议结构：
- 系统设定：你是知识图谱导航员
- 任务描述：从起点实体出发，推理可回答问题的目标实体
- 用户问题：`question`
- 起点实体：`q_entity`
- 输出：`推理路径:`

### 2.2 验证元数据
该数据不输入模型，仅用于奖励函数计算。

建议字段：
- `a_entity`（真实答案/目标终点实体）


> 因为 `prefix_allowed_tokens_fn` 已保障结构合法，奖励函数可不再处理“路径是否在图谱内”的校验逻辑。

---

## 第三部分：奖励函数极简设计

奖励函数只关注：**语义相关度 + 推理效率**。

对同一问题生成的 `G` 条路径分别打分：

### 3.1 终极目标命中奖
- 提取路径终点节点 `Final Node`
- 若 `Final Node == a_entity`：奖励 `+10.0`

### 3.2 语义接近得分
- 若未命中终点，不直接置 0，避免梯度稀疏
- 使用轻量向量模型（如 `BGE-m3`）计算终点与 `a_entity` 余弦相似度
- 奖励建议：`sim * 3.0`

### 3.3 绕路惩罚
- 若路径出现绕圈或明显过长，按 hop 惩罚
- 建议：超过预期 hop 后，每多一跳 `-0.5`

## 第四部分：A800（80GB）推荐参数

### 4.1 LoRA 参数
- `r = 64`
- `alpha = 128`
- `target_modules = [q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj]`

### 4.2 GRPO / 生成参数
- `num_generations (G) = 4`
- `max_new_tokens = 64 ~ 128`
- `temperature = 0.8 ~ 0.9`

> 温度不能太低，否则组内样本同质化，优势值退化。

### 4.3 优化器与训练参数
- `learning_rate = 1e-6 ~ 3e-6`
- `per_device_train_batch_size = 1`
- `gradient_accumulation_steps = 8`（等效 batch size = 8）
- `kl_penalty_beta = 0.04`

> 强化学习阶段学习率必须显著低于 SFT 常用学习率，避免 KL 爆炸。

## 最终预期收益

### 绝对无结构幻觉
通过 Trie + `prefix_allowed_tokens_fn`，模型无法输出图谱外 token 路径。

### 高命中率
通过 GRPO 的相对偏好优化，模型在多个合法分支中更倾向选择能到达正确答案终点的路径。

即：
- 不是“会不会走图谱”的问题（已由约束保证）
- 而是“在合法分支里选哪条更对”的问题（由 GRPO 学习解决）
