# 研究方向调整汇报：从图约束推理转向 LLM + 图搜索

更新日期：2026-04-24

## 一、摘要

本次汇报希望说明一个明确的研究方向调整：

- 原方向：以 `Graph-Constrained Reasoning (GCR)` / `KG-Trie` 为核心的图约束推理与路径生成。
- 新方向：以 `LLM + 图搜索` 为核心，把大模型作为理解、规划、调度与总结模块，把图搜索作为可信证据获取与执行模块。

---

## 二、为什么要调整研究方向

### 2.1 当前系统已经证明：合法性不是唯一瓶颈

前期围绕 GCR / KG-Trie 的梳理和实验已经说明，当前方案最强的能力是：

- 能保证生成路径在知识图谱上合法；
- 能显著降低越界生成和结构性幻觉；
- 路径可追踪、可解释，faithfulness 较强。

但随着代码梳理、训练调试和交互链路打通，也暴露出一个越来越明确的问题：

- 模型经常能生成“合法路径”，但这些路径并不命中答案；
- 即使路径在图中可达，也不代表它与问题真正相关；
- 训练时如果完全依赖模型自己探索，容易出现奖励过弱、监督不足、有效学习信号不稳定的问题。

这意味着当前阶段的核心矛盾，已经从“路径是否合法”转向：

> 合法路径是否足够接近目标答案，是否能够提供有效证据，是否能形成稳定的学习信号。

### 2.2 图约束推理本质上仍然是“受限搜索”，而不是“目标导向搜索”

当前 GCR 管线的本质可以概括为：

`问题实体附近所有合法路径 -> trie 约束 beam search -> 直接输出`

这个流程对“合法性”很强，但对“相关性”没有独立建模层。问题主要体现在以下几方面。

#### （1）候选空间是“可达空间”，不是“目标空间”

当前做法是从问题实体出发，按固定 hop 枚举路径，只要路径在图中存在，就会进入候选集合。这样构造出的候选空间能保证：

- 路径合法；
- 路径可达；
- 路径符合图结构。

但不能保证：

- 路径与问题语义匹配；
- 路径能提供回答问题所需的核心证据；
- 路径终点满足答案类型约束。

因此，只要起点实体邻边较多，候选空间里就会天然混入大量“合法但无关”的路径。

#### （2）当前排序仍主要依赖语言模型概率

虽然路径生成受 trie 约束，但 beam search 的排序本质上仍主要依赖语言模型分数。这会天然偏向：

- 高频关系；
- 语言上更顺滑、更模板化的路径表达；
- 分支更多、延展性更强的节点。

这些偏好不一定等于“更能回答当前问题”。

#### （3）固定 hop 会放大噪声

当前实现中，固定深度的 DFS / index path length 有明显局限：

- 对简单问题来说，hop 过长会引入大量无关边；
- 对复杂问题来说，hop 不够又无法覆盖真实推理链；
- 系统更像“局部可达路径枚举器”，而不是“目标导向的搜索器”。

#### （4）缺少“证据充分性”判断

当前系统能判断“能不能继续生成”，但不擅长判断：

- 这条路径是否已经足以支持答案；
- 是否应该继续扩展；
- 是否已经偏题，应当停止或回退。

没有这一层，系统就容易保留大量“仍然合法、但已经无助于解题”的路径。

#### （5）约束机制本身还存在泄漏风险

现有约束解码里，当 trie 前缀匹配失败时，存在回退到“允许所有 token”的逻辑。这样会带来两个问题：

- 约束并不是全程严格生效；
- 后续结果中可能混入“相关性问题”和“约束泄漏问题”。

这说明，哪怕继续强化图约束，也未必能直接解决“问题相关性”这一主矛盾。

## 三、为什么新方向是 LLM + 图搜索

### 3.1 图搜索更符合当前任务的本质

无论是图约束生成，还是路径推理，底层其实都离不开搜索。区别在于：

- 图约束推理更偏“在合法候选空间中生成”；
- 图搜索更偏“围绕问题目标，逐步获取证据”。

对于知识图谱问答、可信推理、多跳检索这类任务，真正关键的往往不是“生成一条像样的路径”，而是：

- 能否先找到正确实体；
- 能否选择正确关系；
- 能否控制搜索分支；
- 能否在恰当深度停止；
- 能否得到可验证、可回溯的证据链。

这些问题天然更适合用“图搜索”建模，而不是只用“受约束的文本生成”建模。

### 3.2 LLM 和图搜索的职责分工更清晰

新方向里，LLM 和图搜索可以形成非常自然的分工：

#### 图搜索负责

- 基于实体和关系在图中进行精确检索；
- 约束搜索空间，提供事实级证据；
- 控制 hop、路径、候选子图和答案集合；
- 保证证据落在图谱上，降低幻觉。

#### LLM 负责

- 听懂自然语言问题；
- 抽取实体、关系、目标类型；
- 做问题分解、关系预测、搜索规划；
- 对候选路径或子图做相关性判断；
- 对搜索结果做证据整合和自然语言回答。

也就是说，图搜索负责“找真证据”，LLM 负责“理解问题、调度工具、解释结果”。这比让一个生成模型同时承担“搜索 + 推理 + 表达”三件事更稳定。

### 3.3 对可信性和工程落地更友好

如果要做一个真正可用的可信推理系统，仅靠自由生成很难满足要求。相比之下，`LLM + 图搜索` 更符合工程落地需求：

- 图搜索结果天然可验证；
- 搜索路径和子图可直接展示；
- 可以把查询逻辑封装成 tool / function calling；
- 失败点更清楚，便于调试和重试；
- 更适合接知识库、图数据库和业务系统。

尤其在要求较高的场景中，业界更稳定的方案通常不是让大模型自由写查询，而是：

- 先做实体对齐；
- 再注入 schema；
- 再生成查询或直接调用图检索工具；
- 最后把结果交给 LLM 总结。

如果系统追求更高稳定性，还可以进一步把图查询封装成固定 API，让 LLM 只做参数抽取和工具调度。

## 四、调研结论：当前领域的主线也在转向“相关性优先”

结合前期调研文档，可以把近期 KG + LLM 推理问答的主线概括为一句话：

> 研究重点已经从“只保证路径合法”，逐步转向“合法 + 相关 + 可验证 + 可自纠”。

### 4.1 当前主流路线可以概括为四类

#### （1）KG-RAG / 子图检索路线

代表思路是：

- 先从 KG 中取相关事实、路径或子图；
- 再把这些结构化证据交给 LLM 推理。

这一类方法最强调的是：

- 不要把整个图或大量噪声路径都交给 LLM；
- 相关性控制最好发生在 LLM 之前。

#### （2）计划优先 / 查询优先路线

代表思路是：

- 先把自然语言问题转成更结构化的表示；
- 再据此去图中检索和执行。

这类方法的共同点是：

- 不让模型直接在大图中“盲走”；
- 而是先明确要找什么、找哪类关系、目标实体应该是什么类型。

#### （3）Agent 式图搜索路线

这一类方法最接近我们拟转向的方向。它们通常把推理拆成多个步骤：

- 看当前证据；
- 判断下一步往哪走；
- 扩展候选关系或节点；
- 判断当前证据是否足够；
- 不够就继续，偏题就回退。

这类方法解决“合法但不相关”的能力最强，因为它把“相关性”变成了逐步决策问题。

#### （4）图约束解码路线

这一类方法的优势依然明显：

- 合法性强；
- faithfulness 强；
- 路径可解释。

但其局限也越来越清楚：

- 约束通常是“局部可达性约束”，不是“全局问题相关性约束”；
- beam score 更像语言概率，而不是问题相关性分数；
- 对固定 hop、候选空间质量和解码细节较敏感。

### 4.2 调研对当前项目的直接启发

综合已有调研，最适合当前项目的结论不是“彻底抛弃 GCR”，而是：

#### 结论一：相关性控制应当前移

不要等生成结束后再看路径是否相关，而应尽量在以下阶段提前控制：

- 局部子图构造阶段；
- 关系候选筛选阶段；
- 每一步扩展决策阶段。

#### 结论二：要把“搜索”从隐式过程变成显式过程

当前很多问题之所以难分析，是因为搜索发生在 beam 和 token 级生成里，不够显式。若改成显式图搜索，就能更清楚地回答：

- 为什么扩展这条边；
- 为什么保留这个候选；
- 为什么在这里停止；
- 为什么判定这个答案更可信。

#### 结论三：问题分解是自然的增强方向

对于复杂多跳问题，与其一次性生成完整长路径，不如：

- 先把复杂问题分解为若干子问题；
- 对每个子问题做实体和关系对齐；
- 再汇总多步搜索结果。

这条路线对长链推理、多答案检索、复杂约束问题更友好。

#### 结论四：图搜索比直接自由写 Cypher 更稳

在复杂 schema、私有图谱和中文问答场景中，直接让 LLM 裸写查询语句存在较高失败率。因此更合理的工程路线通常是：

- 实体抽取与标准化；
- schema 注入；
- 查询生成与错误反馈；
- 或进一步改为 function calling / tool use。

## 五、前期工作并没有浪费，反而为新方向打下了基础

这次转向不是推倒重来。前期围绕图约束推理所做的大量工作，实际上已经为 `LLM + 图搜索` 提供了基础模块。

### 5.1 对现有图约束链路的系统梳理，已经帮我们定位了真正瓶颈

前期我们已经完成了对以下模块的系统性阅读和梳理：

- prompt 构造；
- 特殊 token 注入；
- trie 构造；
- 约束解码逻辑；
- 停止条件；
- 训练与评测链路。

这使我们能够明确分辨：

- 哪些问题是合法性问题；
- 哪些问题是相关性问题；
- 哪些问题是训练信号问题；
- 哪些问题是工程实现问题。

这一步非常重要，因为没有这轮梳理，就无法有把握地提出“研究主线应该调整”。

### 5.2 交互式客户端原型已经补齐了图搜索所需的关键环节

围绕 `interactive_client`，已经做出的工作包括：

- 建立了交互式推理入口，支持单轮和多轮提问；
- 把实体抽取、局部子图构造、路径候选搜索接入到同一条链路；
- 打通了“问题输入 -> 实体识别 -> 局部子图构建 -> trie 构造 -> 图约束生成 -> 结果输出”的完整流程；
- 完成了图谱加载、局部子图裁剪、候选路径排序与截断。

这说明我们已经不再停留在离线推理脚本，而是初步具备了“问题驱动的局部图操作能力”。这正是图搜索系统的雏形。

### 5.3 已有实体抽取和图存储模块，天然可以转成搜索前端

当前已经具备：

- 轻量实体抽取能力；
- 候选实体打分和交互选择能力；
- 基于起始实体的 K-hop 子图抽取；
- 对局部子图规模的控制。

这些模块在新方向下不但仍然可用，而且会更重要，因为它们正好对应图搜索流程中的前置步骤：

- 实体定位；
- 搜索空间裁剪；
- 局部图构造；
- 候选路径生成。

### 5.4 数据和工程基础已经足以支撑下一步验证

根据当前交互客户端的静态统计，现有图数据规模已经达到：

- 图谱记录数约 79 万；
- 去重后三元组约 78 万；
- 实体规模约 11 万。

在这个规模下，继续做“全局自由生成”会越来越难控，而做“局部子图 + 目标导向搜索”反而更合理。

## 六、新研究方向的定义与技术路线

### 6.1 新方向的核心表述

新的研究方向可以表述为：

> 面向知识图谱可信推理问答，研究一种由大语言模型驱动的问题理解、规划与验证机制，以及由图搜索负责证据检索与执行的协同框架。

再简单一点说，就是：

> 让 LLM 负责“问什么、怎么找、何时停、如何说”，让图搜索负责“沿着图真实地找到证据”。

### 6.2 一个更清晰的系统架构

建议将后续系统架构明确划分为三层。

#### 第一层：合法性层

职责：

- 保证路径、边和候选扩展都落在知识图谱上；
- 保留现有 GCR / KG-Trie 的部分能力；
- 作为底层 faithful execution 机制存在。

#### 第二层：相关性层

职责：

- 根据问题对实体、关系、路径、子图进行打分；
- 过滤明显无关的候选；
- 让搜索更像“问题驱动”，而不是“局部可达枚举”。

可能采用的技术包括：

- embedding 相似度；
- cross-encoder 路径打分；
- relation gating；
- 问题条件下的子图重排。

#### 第三层：充分性层

职责：

- 判断当前证据是否足够回答问题；
- 决定是否继续扩展；
- 支持动态深度搜索与停止控制。

这一层会直接提升系统的可控性和效率。

### 6.3 推荐的核心流程

后续建议重点推进的流程如下：

`问题输入 -> 实体抽取/对齐 -> 目标关系或答案类型预测 -> 局部子图构建 -> 图搜索/候选扩展 -> 路径或子图相关性重排 -> 证据充分性判断 -> LLM 总结回答`

这条流程相比原来的优势在于：

- 搜索空间更可控；
- 每个步骤更可解释；
- 更容易定位错误发生在哪一层；
- 更方便插入调研中提到的 rerank、gating、verifier、decomposition 等模块。

## 七、建议的阶段性研究计划

### 7.1 第一阶段：在现有基础上做“最小改造版图搜索”

目标：不大改框架，先验证“相关性建模”是否确实能显著提升效果。

建议优先做四件事：

1. 增加日志和诊断信息。
2. 在候选路径输出后增加 post-hoc reranker。
3. 给路径增加支持度 / 充分性判断。
4. 记录约束 fallback、空结果率、有效路径率等指标。

这一阶段的价值在于：

- 改动小；
- 实验可解释；
- 能快速验证转向是否成立。

### 7.2 第二阶段：从“后验重排”走向“搜索前置控制”

目标：把相关性控制从结果端前移到搜索端。

建议推进：

- relation gating；
- 答案类型约束；
- 局部子图重排；
- 动态深度扩展；
- 复杂问题分解。

这一阶段会使系统从“合法路径生成器”逐步变成“问题导向搜索器”。

### 7.3 第三阶段：形成真正的 LLM + 图搜索协同框架

目标：把 LLM 真正变成搜索控制器，而不仅仅是答案生成器。

建议推进：

- tool calling / function calling 风格的图搜索接口；
- 分步搜索状态管理；
- 多轮搜索、验证、回退；
- 证据路径与答案联合输出；
- 更强的可视化与交互式解释。

到这一步，系统就会从“图约束推理实验框架”升级为“可信图搜索问答系统”。

---

## 八、评测指标也应同步调整

如果研究方向发生变化，评测指标也应从“路径是否生成正确”扩展到“搜索是否有效”。

建议后续重点关注以下指标：

- answer accuracy / F1；
- top-k path relevance；
- gold path hit rate；
- 有效候选路径比例；
- 平均搜索步数；
- 实体对齐准确率；
- 空结果率；
- fallback 触发比例；
- 证据支持度判断准确率。

这些指标更能反映 `LLM + 图搜索` 体系的真实收益。

## 九、可能的质疑与回应口径

### 质疑一：这是不是意味着前面的 GCR 工作做偏了？

回应：

不是。前期 GCR 工作解决了一个非常关键的问题，即如何保证路径合法、如何让推理链条落在图上。没有这部分工作，就无法看清当前系统的真正瓶颈，也无法为后续图搜索系统提供 faithful execution 的底座。

### 质疑二：为什么不继续把 GCR 做强，而是换方向？

回应：

因为当前主要瓶颈已经不是“合法性不足”，而是“相关性不足”和“证据充分性不足”。如果继续只强化 GCR，会越来越偏向局部解码优化，难以直接解决主问题。转向图搜索并不是放弃已有能力，而是把研究焦点放到更核心、更高价值的问题上。

### 质疑三：是不是最终完全不做图约束了？

回应：

也不是。图约束能力仍然保留，而且非常有价值，但它更适合作为底层合法性层，而不是整个系统唯一的中心机制。

### 质疑四：为什么一定要加 LLM，不能只做图搜索？

回应：

纯图搜索擅长精确执行，但不擅长处理自然语言问题中的模糊表达、复杂意图、问题分解和结果表达。LLM 的价值不在于替代图搜索，而在于：

- 理解问题；
- 规划搜索；
- 调度工具；
- 总结证据。

---

## 十、汇报时建议使用的结论表述

如果会议上需要一句话说明这次调整，可以直接使用下面这段：

> 前一阶段我们围绕图约束推理做了较系统的机制梳理、训练改造和交互原型搭建，已经证明现有方案在路径合法性和可追踪性上是有效的。但随着实验推进，当前主矛盾已经从“路径是否合法”转向“合法路径是否真正相关、是否足以支撑答案”。因此我建议把研究主线从图约束推理调整为 LLM + 图搜索：由 LLM 负责问题理解、规划、验证和总结，由图搜索负责真实证据获取和执行；原有图约束能力保留为底层合法性保障模块。这个方向更贴近当前 KG + LLM 的主流研究趋势，也更适合做成可验证、可解释、可落地的可信推理系统。

## 十一、建议的汇报提纲（可直接做 PPT）

### 1. 研究背景

- 知识图谱推理需要可信、可解释、可验证；
- 纯 LLM 容易幻觉；
- 图约束推理能保证合法性，但不等于高相关性。

### 2. 前期工作

- 梳理 GCR / KG-Trie 机制；
- 工程化改造训练与推理流程；
- 搭建交互式客户端；
- 打通实体抽取、局部子图、候选路径和约束生成。

### 3. 当前发现的核心问题

- 合法路径不一定命中答案；
- 固定 hop 会引入大量噪声；
- beam score 偏语言概率而非问题相关性；
- 缺少证据充分性判断。

### 4. 调研结论

- 当前主流从“合法性优先”走向“相关性优先”；
- 相关性控制应前移；
- 计划优先、子图检索、Agent 图搜索、tool calling 都值得借鉴。

### 5. 新方向

- 从图约束推理转向 LLM + 图搜索；
- LLM 负责理解、规划、验证、总结；
- 图搜索负责检索、执行、返回证据。

### 6. 与原方向的关系

- 不是推倒重来；
- GCR 保留为合法性层；
- 新系统在其上补相关性层和充分性层。

### 7. 下一步计划

- 短期：rerank + verifier + 日志诊断；
- 中期：relation gating + 动态深度 + 问题分解；
- 长期：tool-calling 风格的 Agent 图搜索系统。

---

## 十二、总结

这次研究方向调整的核心，不是简单从一个方法换到另一个方法，而是对问题本质的重新聚焦：

- 原来更关注“如何在图上合法生成”；
- 现在更关注“如何围绕问题找到真正有用的图上证据”。

从这个角度看，`LLM + 图搜索` 并不是对已有工作的否定，而是基于已有工作自然演化出来的下一阶段方向。前期的 GCR 研究、代码梳理、训练改造和交互式原型，已经为这次转向打下了很好的基础。

如果后续推进顺利，这条路线有望把当前项目从“图约束路径生成框架”升级为“可信、可解释、可扩展的图搜索问答系统”。
